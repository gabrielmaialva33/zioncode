# BLIVRE ARC CLI demo

Date: 2026-08-29

This script demonstrates a reproducible offline import, capacity report, one-book seal, authenticated open, wrong-passphrase rejection, and optional 66-book batch. It uses a generated codec-test carrier so the commands are self-contained; replace it with separately licensed RGB8 artwork for a presentation.

Run these Bash commands from the repository root. The commands never place a passphrase in the argument list.

## 1. Build and acquire the pinned source

```bash
cargo build --release -p zion-cli

DEMO_DIR="$(mktemp -d /tmp/zion-arc-demo.XXXXXX)"
curl --fail --location \
  --output "$DEMO_DIR/usfm-blivre-tr.zip" \
  https://github.com/blivre/BibliaLivre/releases/download/2018.2.0/usfm-blivre-tr.zip

test "$(stat -c %s "$DEMO_DIR/usfm-blivre-tr.zip")" -eq 1364020
printf '%s  %s\n' \
  83e5435706b2d640d0b35b690b0cf0a4508d910dd26b895d155c37a670729ead \
  "$DEMO_DIR/usfm-blivre-tr.zip" |
  sha256sum --check --status
```

The corpus download is the only runtime-data network-dependent step. An uncached Cargo build may also fetch Rust dependencies. The importer and ARC operations are otherwise offline. The source release and licensing record are in [the versioned provenance document](../provenance/blivre-2018.2.0.md).

## 2. Import and prove private package modes

```bash
(
  umask 000
  ./target/release/zion arc blivre import \
    "$DEMO_DIR/usfm-blivre-tr.zip" \
    --output-dir "$DEMO_DIR/corpus"
)

test -z "$(find "$DEMO_DIR/corpus" -type d ! -perm 0700 -print -quit)"
test -z "$(find "$DEMO_DIR/corpus" -type f ! -perm 0600 -print -quit)"
find "$DEMO_DIR/corpus" -type d | wc -l
find "$DEMO_DIR/corpus" -type f | wc -l
```

Expected counts are four directories and 137 files. Import refuses an existing output directory. The package keeps normalized payloads in `books/` and the immutable ZIP, upstream notices, `SOURCE.json`, and 66 byte-exact USFM files under `provenance/`.

## 3. Analyze all 66 books

```bash
./target/release/zion arc blivre analyze \
  "$DEMO_DIR/usfm-blivre-tr.zip" \
  --width 1080 \
  --height 2340 \
  --profile safe
```

The final line must be `all_books_fit yes`. The measured table is recorded in [the fit report](../results/2026-08-29-blivre-arc-fit.md). Psalms is the largest normalized payload: 657,274 JSON bytes and 123,349 ARC zstd-6 bytes, requiring 556 codewords and 1,134,240 payload bits with the canonical batch metadata.

## 4. Prepare an RGB8 carrier and metadata

```bash
./target/release/zion optical-render Cargo.toml \
  --output "$DEMO_DIR/cover-1080x2340.png" \
  --width 1080 \
  --height 2340

file "$DEMO_DIR/cover-1080x2340.png"
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,pix_fmt \
  -of default=noprint_wrappers=1 \
  "$DEMO_DIR/cover-1080x2340.png"

printf '%s' \
  'Todas as Escrituras em português citadas são da Bíblia Livre (BLIVRE), Copyright © Diego Santos, Mario Sérgio, e Marco Teles, http://sites.google.com/site/biblialivre/ - fevereiro de 2018. Licença Creative Commons Atribuição 3.0 Brasil (https://creativecommons.org/licenses/by/3.0/br/). The normalized JSON retains byte-exact, exportable source USFM and its pinned provenance.' \
  > "$DEMO_DIR/blivre-attribution.txt"

test "$(stat -c %s "$DEMO_DIR/blivre-attribution.txt")" -eq 384
printf '%s  %s\n' \
  459e4e5585e1ee8692f07aa947fe08b200f5e40afc09e46961fda42c5d5d070d \
  "$DEMO_DIR/blivre-attribution.txt" |
  sha256sum --check --status

openssl rand -out "$DEMO_DIR/passphrase.bin" 32
chmod 600 "$DEMO_DIR/passphrase.bin"
```

Expected carrier inspection is 1080x2340 `rgb24`: an 8-bit RGB, non-interlaced PNG. `zion arc seal` also validates this contract. The passphrase is opaque random bytes; its value is not printed or logged. A real operator should transfer it separately through an appropriate channel.

## 6. Seal and open Psalms

```bash
(
  umask 000
  ./target/release/zion arc seal \
    "$DEMO_DIR/corpus/books/19-PSA.json" \
    "$DEMO_DIR/cover-1080x2340.png" \
    --output "$DEMO_DIR/19-PSA.arc.png" \
    --name '19 — Salmos' \
    --media-type 'application/vnd.zion.blivre+json' \
    --attribution-file "$DEMO_DIR/blivre-attribution.txt" \
    --profile safe \
    --passphrase-file "$DEMO_DIR/passphrase.bin"

  ./target/release/zion arc open \
    "$DEMO_DIR/19-PSA.arc.png" \
    --output "$DEMO_DIR/19-PSA.opened.json" \
    --passphrase-file "$DEMO_DIR/passphrase.bin"
)

test "$(stat -c %a "$DEMO_DIR/19-PSA.opened.json")" = 600
sha256sum \
  "$DEMO_DIR/corpus/books/19-PSA.json" \
  "$DEMO_DIR/19-PSA.opened.json"
cmp "$DEMO_DIR/corpus/books/19-PSA.json" "$DEMO_DIR/19-PSA.opened.json"
```

Both JSON hashes must be:

```text
0b2f3d28602f0d945a6166f746c70d11f55c8a1528bf17998beb9d8570b8db6f
```

The measured run produced 556 codewords and 123,988 ciphertext bytes. The output JSON is created as `0600` at open time even under `umask 000`. Seal and open refuse an existing output path.

Collection IDs, capsule IDs, salt, nonce, placement, ciphertext, PNG size, and PNG hash change on each seal. Stable geometry and an identical authenticated plaintext are the expected result; matching a recorded ARC PNG hash is not.

If `rhash` with BLAKE3 support is installed, the post-patch reference run measured `860fc75947f898f1561565309988239ec13365040741c72010de3ba1238bf477` for both the input and opened JSON, and `239668f5c634d06730be9ed65137db9101e39d008c72937eabf1e298fc9c36f3` for that run's ARC PNG. SHA-256 is the normative corpus identity recorded in the manifest; the ARC image hash changes on reseal.

## 7. Show wrong-passphrase rejection

```bash
openssl rand -out "$DEMO_DIR/wrong-passphrase.bin" 32
chmod 600 "$DEMO_DIR/wrong-passphrase.bin"

if ./target/release/zion arc open \
  "$DEMO_DIR/19-PSA.arc.png" \
  --output "$DEMO_DIR/must-not-exist.json" \
  --passphrase-file "$DEMO_DIR/wrong-passphrase.bin"
then
  printf '%s\n' 'unexpected success' >&2
  exit 1
fi

test ! -e "$DEMO_DIR/must-not-exist.json"
```

The public CLI reports a generic capsule-recovery failure and leaves no plaintext output. It does not disclose whether a password, authentication tag, envelope, ECC result, or content hash caused recovery to fail.

## 8. Optional exact 66-book batch

The batch command requires an exact set of 66 canonical filenames such as `01-GEN.png`, `19-PSA.png`, and `66-REV.png`. It rejects missing, extra, noncanonical, invalid-UTF-8, symlink, directory, or non-file entries. This snippet explicitly reuses one test carrier only to exercise the batch path; presentation artwork should provide a separately licensed cover for each book.

```bash
mkdir -m 700 "$DEMO_DIR/covers"

while IFS="$(printf '\t')" read -r ordinal book_id
do
  cover_name="$(printf '%02d-%s.png' "$ordinal" "$book_id")"
  cp "$DEMO_DIR/cover-1080x2340.png" "$DEMO_DIR/covers/$cover_name"
done < <(jq -r '.books[] | [.ordinal, .id] | @tsv' "$DEMO_DIR/corpus/manifest.json")

./target/release/zion arc blivre seal-batch \
  "$DEMO_DIR/usfm-blivre-tr.zip" \
  --covers-dir "$DEMO_DIR/covers" \
  --output-dir "$DEMO_DIR/arc-books" \
  --profile safe \
  --passphrase-file "$DEMO_DIR/passphrase.bin"
```

The command imports through the same pinned verifier, fully preflights the exact cover set, RGB8 decoding, capacity, and final paths, derives one collection key, seals all 66 files in a private same-filesystem staging directory, and publishes only after all seals succeed. Existing final paths are refused.

## What this demo does and does not prove

It proves pinned-source verification, deterministic corpus normalization, measured carrier capacity, authenticated byte-identical recovery, explicit private plaintext/package creation on Unix, overwrite refusal, and bounded offline operation after acquisition.

It does not prove that screenshots or lossy image transformations survive, that a chosen artwork evades steganalysis, that the cryptographic construction has been independently audited, that a mobile reader already enforces these CLI properties, or that transport is legal in every jurisdiction. ARC recovery requires the original dimensions and RGB8 pixel samples in a valid lossless PNG; a lossless PNG re-encode may change container bytes without changing recoverability. Resize, crop, screenshot capture, lossy recompression, or color conversion is unsupported and may destroy the capsule.
