# Zion ARC five-minute hackathon demo

Date: 2026-08-29

Status: the desktop path, three carrier artworks, Android builds, host tests, and
bounded-corruption tooling are available. Do not present the Android sequence
as measured until the physical arm64-device acceptance checklist in the Android
record has passed. Use the desktop fallback below if it has not.

## Before going on stage

1. Build the release CLI and Android APKs from the documented commands.
2. Rebuild the Genesis, Psalms, and Revelation capsules into a private working
   directory; never place the passphrase, imported corpus, opened JSON, or
   sealed Bible capsules in the repository.
3. Create the bounded Psalms fixture with `zion arc corrupt-fixture`, then open
   it and require an exact comparison with the canonical Psalms JSON.
4. Copy only the three sealed PNGs and bounded fixture to the demo device over
   a lossless byte-preserving path. Record their SHA-256 values before and after
   transfer.
5. Clean-install the APK, enable airplane mode, and complete the full acceptance
   run once before the presentation.

## Five-minute sequence

### 0:00–0:35 — Ordinary art, exact files

Show the three 1080×2340 PNG artworks in the system Files app. Say:

> These are ordinary-looking lossless phone artworks. Each exact PNG is also a
> self-contained offline capsule for one complete document. We use no QR
> scanner, camera, cloud account, or network connection.

Do not call them screenshots. ARC's baseline lossless workflow preserves the
original PNG dimensions and RGB8 samples. The measured exception is controlled
payload-bit damage within each codeword's ECC budget; gallery edits,
messaging-app recompression, JPEG, resize, print, and camera capture remain
unsupported.

### 0:35–1:20 — The protocol, not a secret cipher

Show the architecture slide and say:

> Zion ARC compresses the whole item with zstd, derives a collection key with
> Argon2id, authenticates and encrypts with XChaCha20-Poly1305, adds outer
> Reed–Solomon protection, interleaves the codewords, and places their bits in
> passphrase-keyed RGB channel positions. ARC is our open framing and transport
> protocol; the cryptographic primitives are established components.

Point out that the public `ZARC` bootstrap makes capsule existence detectable.
Do not claim invisibility, steganalysis resistance, a novel cipher, or an audit.

### 1:20–2:10 — Open Psalms offline

With airplane mode visible, launch Zion ARC, select the original Psalms PNG via
the document picker, enter the passphrase, and open it. Scroll across two
chapters, then open About/Licenses and show the BLIVRE attribution. Say:

> The app requests no internet permission. It passes original PNG bytes through
> one bounded JNI call to the Rust core, authenticates before releasing content,
> structurally validates the book document, and renders locally.

If physical-device acceptance is still pending, run the equivalent desktop
open and exact `cmp` instead, and say explicitly that this is the fallback.

### 2:10–2:40 — Wrong password

In the Android app, try a wrong password and show the single generic recovery
error with no book content displayed. If physical-device acceptance is still
pending, use the desktop fallback with a fresh output path and show that no
partial output file was created. Never display a terminal command containing a
passphrase; use the protected passphrase file or no-echo prompt.

### 2:40–3:25 — Measured bounded damage

Open the prepared Psalms corruption fixture. Say:

> This fixture deliberately flips one embedded bit in exactly 16 distinct
> bytes of every Safe-profile Reed–Solomon codeword—the documented maximum.
> For the measured 556-codeword Psalms capsule, that is 8,896 corrupted payload
> bytes and 8,896 changed RGB channels, each by only one level. Reed–Solomon
> repairs the ciphertext first; authenticated encryption then proves the
> recovered document is exact.

This is a controlled protocol fixture, not evidence of screenshot, JPEG, crop,
or arbitrary-image-damage survival.

### 3:25–4:20 — Capacity and visual evidence

Show the coded carrier-art and all-book fit reports. Highlight:

- 66 of 66 pinned BLIVRE books fit independently in the 1080×2340 Safe carrier;
- Psalms is the largest normalized book at 657,274 JSON bytes and 556 of 1,226
  available codewords;
- the normal and 5–9 MB lossless PNG encodings have identical sealed RGB
  samples, so PNG file size is presentation—not protocol capacity; and
- clean-versus-sealed PSNR/SSIM and channel deltas are measurements generated by
  the workflow, not slide estimates.

### 4:20–5:00 — What is sold

Close with:

> We are not selling a secret encryption algorithm. We are selling a reliable
> offline delivery product around an inspectable protocol: mobile and Rust SDK
> integration, white-label readers, authorized collection building, provenance
> and release tooling, deployment support, and funded security evaluation.
> Knowledge that travels as art.

State that operators remain responsible for content rights and local law. ARC
does not authorize bypassing inspection or import restrictions.

## Desktop contingency

Use the private files produced by `scripts/build-art-demo.sh`:

```bash
./target/release/zion arc open \
  "$DEMO_DIR/sealed-compression0.arc.png" \
  --output "$DEMO_DIR/psalms.stage-open.json" \
  --passphrase-file "$PASSPHRASE_FILE"

cmp "$CANONICAL_CORPUS/books/19-PSA.json" \
  "$DEMO_DIR/psalms.stage-open.json"

./target/release/zion arc corrupt-fixture \
  "$DEMO_DIR/sealed.arc.png" \
  --output "$DEMO_DIR/psalms.bounded-damage.arc.png" \
  --passphrase-file "$PASSPHRASE_FILE"

./target/release/zion arc open \
  "$DEMO_DIR/psalms.bounded-damage.arc.png" \
  --output "$DEMO_DIR/psalms.bounded-opened.json" \
  --passphrase-file "$PASSPHRASE_FILE"

cmp "$CANONICAL_CORPUS/books/19-PSA.json" \
  "$DEMO_DIR/psalms.bounded-opened.json"
```

Every output path must be new. Keep the entire demo directory private and
unversioned because it contains plaintext validation copies.

## Stop conditions

Switch to the desktop fallback instead of improvising if the device changes the
PNG bytes, the document provider returns a rendition, the app has not passed an
airplane-mode clean-install run, or any hash differs after transfer. Do not
weaken verification or substitute a cached plaintext to save the live demo.
